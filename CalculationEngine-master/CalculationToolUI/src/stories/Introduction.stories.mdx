# Welcome to Storybook
Storybook helps you build UI components in isolation from your app's business logic, data, and context.
That makes it easy to develop hard-to-reach states. Save these UI states as **stories** to revisit during development, testing, or QA.

Browse example stories now by navigating to them in the sidebar.
View their code in the `stories` directory to learn how they work.
We recommend building UIs with a [**component-driven**](https://componentdriven.org) process starting with atomic components and ending with pages.

# Storybook for the ROCKWOOL project
Storybook has been set up to make it easy to implement and test individual components, without needing the whole application and the back-end to run.

## Adding a component
* When you want to add a component, start by adding `[ComponentName].tsx` and `[ComponentName].scss` files in the `components` folder
  * The `components` folder is only for visual components - if the component is purely for application structure, place it in the `infrastructure` folder.
* Implement the input properties needed in the component
* In the `stories` folder, create a `[ComponentName].stories.tsx` (or .mdx) file
  * The easiest way is to copy another story file, and rename it and replace the component references with your component
* In your story file after where the `Template` is created, add a couple of example properties that your component might be called with

# Code Guidelines
* Function-based components should be used instead of Class-based components.
* All style rules should be scoped, so they only apply within the `#calculation-ui` element.
* As much as possible, the css variables defined in `App.scss` should be used to style the component
* Styles that are likely to be changed if the app is integrated to another site (like component colors) should always be based on css variables from `App.scss`
